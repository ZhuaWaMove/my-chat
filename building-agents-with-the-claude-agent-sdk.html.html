🚀 引言：从Claude Code SDK到Claude Agent SDK

Claude Agent SDK是一套工具集合，帮助开发者在Claude Code之上构建强大的代理。在这篇文章中，我们将介绍如何开始使用，并分享我们的最佳实践。

背景： 去年，我们与客户分享了构建高效代理的经验教训。自那时起，我们发布了Claude Code——一个最初为支持Anthropic开发人员生产力而构建的代理式编码解决方案。

在过去的几个月中，Claude Code已经远远超越了编码工具的范畴。在Anthropic，我们一直在将其用于深度研究、视频创作和笔记记录等无数非编码应用。事实上，它已经开始为我们几乎所有主要的代理循环提供动力。

换句话说，为Claude Code提供动力的代理框架（Claude Code SDK）也可以为许多其他类型的代理提供动力。为了反映这一更广泛的愿景，我们将Claude Code SDK重命名为Claude Agent SDK。

在这篇文章中，我们将重点介绍为什么构建Claude Agent SDK，如何使用它构建您自己的代理，并分享从我们团队自身部署中涌现的最佳实践。

💻 核心理念：给Claude一个计算机

关键设计原则

Claude Code背后的关键设计原则是：Claude需要程序员每天使用的相同工具。它需要能够在代码库中找到适当的文件，编写和编辑文件，对代码进行lint检查，运行它，调试，编辑，有时需要迭代执行这些操作直到代码成功。

我们发现，通过让Claude访问用户的计算机（通过终端），它拥有了像程序员一样编写代码所需的一切。

但这也使得Claude在Claude Code中在处理非编码任务方面同样有效。通过为其提供运行bash命令、编辑文件、创建文件和搜索文件的工具，Claude可以读取CSV文件、搜索网络、构建可视化、解释指标，并执行各种其他数字工作——简而言之，使用计算机创建通用代理。

Claude Agent SDK的核心原则

Claude Agent SDK的关键设计原则是为您的代理提供一个计算机，让它们能够像人类一样工作。

🔧 创建新型代理

我们相信，给Claude一个计算机能够解锁构建比以往更有效的代理的能力。例如，使用我们的SDK，开发者可以构建：

1. 投资分析代理

构建能够理解您的投资组合和目标，并通过访问外部API、存储数据和运行代码进行计算来帮助您评估投资的代理。

2. 个人助理代理

构建能够帮助您预订旅行和管理日历，以及安排约会、整理简报等的代理，通过连接到您的内部数据源并在应用程序之间跟踪上下文。

3. 客户支持代理

构建能够处理高模糊性用户请求（如客户服务工单）的代理，通过收集和审查用户数据、连接到外部API、向用户发送消息以及在需要时升级到人工处理。

4. 研究代理

构建能够在大型文档集合中进行全面研究的代理，通过搜索文件系统、分析和综合来自多个来源的信息、跨文件交叉引用数据，并生成详细报告。

核心价值： 从核心上讲，SDK为您提供了构建自动化任何工作流程所需的原语。

🔄 构建代理循环

代理循环：收集上下文 → 执行操作 → 验证工作 → 重复

在Claude Code中，Claude通常在一个特定的反馈循环中运行。代理通常在特定的反馈循环中运行：收集上下文 → 执行操作 → 验证工作 → 重复。

1
收集上下文

获取和更新自己的上下文信息

2
执行操作

使用工具完成任务

3
验证工作

检查和改进输出

这为思考其他代理以及应该赋予它们的能力提供了一种有用的方式。为了说明这一点，我们将通过一个示例来介绍如何使用Claude Agent SDK构建一个电子邮件代理。

在开发代理时，您希望给予它的不仅仅是提示：它需要能够获取和更新自己的上下文。以下是SDK中的功能如何提供帮助。

📚 收集上下文

1. 代理式搜索和文件系统

文件系统代表可以拉入模型上下文的信息。当Claude遇到大型文件（如日志或用户上传的文件）时，它将决定如何使用bash脚本（如grep、head、tail）将这些文件加载到其上下文中。

本质上，代理的文件夹和文件结构成为其长期记忆的一种形式。我们的电子邮件代理可能将以前的对话存储在名为"Conversations"的文件夹中。这将允许它在被询问时搜索这些内容作为上下文。

2. 语义搜索

语义搜索通常比代理式搜索更快，但准确性较低，维护更困难，透明度更低。它涉及将相关上下文"分块"，将这些块嵌入为向量，然后通过查询这些向量来搜索概念。

鉴于其局限性，我们建议从代理式搜索开始，只有在需要更快结果或更多变体时才添加语义搜索。

3. 子代理

Claude Agent SDK默认支持子代理。子代理主要有两个原因有用：

  • 并行化： 您可以启动多个子代理同时处理不同的任务
  • 上下文管理： 子代理使用自己隔离的上下文窗口，只将相关信息发送回编排器，而不是它们的完整上下文

这使得它们非常适合需要筛选大量信息（其中大部分信息可能无用）的任务。在设计电子邮件代理时，我们可能会赋予它"搜索子代理"能力。电子邮件代理然后可以并行启动多个搜索子代理——每个运行不同的查询来搜索您的电子邮件历史记录——并让它们只返回相关摘录而不是完整的电子邮件线程。

4. 上下文维护

当代理长时间运行时，上下文维护变得至关重要。Claude Agent SDK的compact功能在上下文限制接近时自动汇总以前的消息，因此您的代理不会用完上下文。

这是基于Claude Code的compact斜杠命令构建的。

⚡ 执行操作

一旦收集了上下文，您将希望给代理灵活的执行方式。

1. 工具

工具是代理执行的主要构建块。工具在Claude的上下文窗口中很突出，使其成为Claude决定如何完成任务时主要考虑的操作。这意味着您应该有意识地设计工具以最大化上下文效率。

您的工具应该是您希望代理采取的主要操作。在我们的电子邮件代理中，我们可能会将工具如"send_email"、"search_emails"定义为代理的主要、最频繁的操作。

最佳实践： 更多工具设计最佳实践请参阅我们的博客文章使用代理编写有效工具。了解如何在Claude Agent SDK中制作工具。

2. Bash命令

Bash作为通用工具很有用，允许代理使用计算机进行灵活的工作。在我们的电子邮件代理中，用户可能在附件中存储了重要信息。Claude可以编写代码下载PDF，将其转换为文本，并通过调用bash命令来搜索它以查找有用信息。

3. 代码生成

Claude Agent SDK擅长代码生成——这是有充分理由的。代码精确、可组合且无限可重用，使其成为需要可靠执行复杂操作的代理的理想输出。

在构建代理时，考虑：哪些任务会受益于用代码表达？通常，答案会解锁显著的能力。

例如，我们最近推出的Claude for Microsoft Office完全依赖于代码生成。Claude编写Python脚本来创建Excel电子表格、PowerPoint演示文稿和Word文档，确保一致的格式和复杂的功能，这些很难通过其他方式实现。

在我们的电子邮件代理中，我们可能希望允许用户为入站电子邮件创建规则。为了实现这一点，我们可以编写代码在该事件上运行。

4. 模型上下文协议（MCP）

模型上下文协议（MCP）提供与外部服务的标准化集成，自动处理身份验证和API调用。这意味着您可以将代理连接到Slack、GitHub、Google Drive或Asana等工具，而无需编写自定义集成代码或自行管理OAuth流程。

对于我们的电子邮件代理，我们可能希望搜索Slack消息以了解团队上下文，或者查看是否已有人被分配处理客户请求。通过MCP服务器，这些集成开箱即用——您的代理可以简单地调用search_slack_messages或get_asana_tasks等工具，MCP会处理其余部分。

优势： 这意味着随着预构建集成的可用，您可以快速为代理添加新功能，让您专注于代理行为。

✅ 验证工作

Claude Code SDK通过评估其工作来完成代理循环。能够检查和改进自己输出的代理从根本上更可靠——它们在错误复合之前捕获错误，在偏离时自我纠正，并在迭代中变得更好。

关键是给Claude具体的方式来评估其工作。以下是我们发现有效的三种方法：

1. 规则验证

最佳的反馈形式是为输出提供明确定义的规则，然后解释哪些规则失败以及原因。

Linting是规则反馈的极佳形式。反馈越深入越好。例如，生成TypeScript并对其进行lint检查通常比生成纯JavaScript更好，因为它为您提供了多个额外的反馈层。

在生成电子邮件时，您可能希望Claude检查电子邮件地址是否有效（如果无效则抛出错误），以及用户之前是否向该地址发送过电子邮件（如果是则发出警告）。

2. 视觉反馈

当使用代理完成视觉任务（如UI生成或测试）时，视觉反馈（以截图或渲染的形式）可能会有所帮助。例如，如果发送带有HTML格式的电子邮件，您可以截图生成的电子邮件，并将其提供回模型进行视觉验证和迭代改进。

然后模型将检查视觉输出是否与请求匹配：

  • 元素位置是否正确？间距是否合适？
  • 颜色、字体和格式是否按预期显示？
  • 信息是否以正确的顺序和适当的重点呈现？
  • 它看起来是否破损或拥挤？（尽管单张截图有有限的视口信息）

使用像Playwright这样的MCP服务器，您可以在代理的工作流程中自动化此视觉反馈循环——截取渲染的HTML截图、捕获不同的视口大小，甚至测试交互元素。

3. 语言模型判断

来自大型语言模型（LLM）的视觉反馈可以为代理提供有用的指导。您还可以让另一个语言模型根据模糊规则"判断"代理的输出。

这通常不是非常稳健的方法，可能有较重的延迟权衡，但对于任何性能提升都值得成本的应用，这可能会有帮助。

我们的电子邮件代理可能有一个单独的子代理来判断其草稿的语气，看看它们是否与用户以前的消息很好地匹配。

🔍 测试和改进代理

在完成几次代理循环后，我们建议测试您的代理，并确保它为其任务做好了充分准备。

改进代理的最佳方法

改进代理的最佳方法是仔细查看其输出，特别是失败的情况，并站在它的角度思考：它是否具备成功所需的正确工具和信息？

在评估代理是否适合其工作时，请考虑以下问题：

上下文问题： 如果代理误解了任务，它可能缺少关键信息。您能否更改搜索API的结构，使其更容易找到需要知道的内容？

错误恢复： 如果代理反复在任务上失败，您能否在工具调用中添加正式规则来识别和修复故障？

能力提升： 如果代理无法修复其错误，您能否为其提供更有用或更具创造性的工具，以不同的方式处理问题？

性能评估： 如果代理的性能随着添加功能而变化，请基于客户使用情况构建代表性的测试集进行程序化评估（或评估）。

🎯 总结

Claude Agent SDK通过让Claude访问计算机（可以在其中编写文件、运行命令和迭代其工作）使构建自主代理变得更加容易。

核心建议

以代理循环为思路（收集上下文、执行操作和验证工作），您可以构建易于部署和迭代的可靠代理。

立即开始使用Claude Agent SDK。对于已经在SDK上构建的开发人员，我们建议通过遵循迁移指南迁移到最新版本。
